# Edward — приватный мессенджер для двоих

Собственный сервер (JS/Express + Socket.IO) + веб-клиент (HTML/CSS/JS).
Работает без магазинов приложений: друг просто открывает ссылку в браузере.
Никаких сторонних серверов — всё крутится на твоём телефоне.

## Аудит и что было исправлено в этой версии

Прошёлся по всему проекту (server.js, db.js, package.json, index.html,
app.js, style.css) и проверил связку фронтенд↔бэкенд по чек-листу:

**Убрано по твоей просьбе (не нужно для задачи):**
- QR-сканер и генерация QR-кода (кнопки, модалки, camera-loop на jsQR) —
  добавление контакта теперь только через поиск по username во вкладке «Люди».
- Эндпоинт `GET /api/user/:id`, который был нужен только для QR-потока.

**Исправлено / докручено:**
- **CORS** — добавлены заголовки `Access-Control-Allow-*` на случай, если
  фронтенд когда-нибудь будет открываться не с того же адреса, что сервер
  (сейчас всё и так на одном origin, но проверка была в списке — сделано).
- **Онлайн/офлайн** — раньше статус показывался только в открытом чате.
  Теперь `GET /api/users` возвращает `online: true/false` по каждому
  пользователю, и зелёная точка появляется в списках «Люди» и «Чаты»,
  обновляясь в реальном времени по событию `presence`.
- **Путь A → сервер → B для звонков проверен целиком:**
  `call:offer` → сервер ищет активный сокет собеседника → если его нет
  (человек не в сети), теперь отправляется `call:unavailable` и звонок
  сразу корректно завершается с понятным статусом, а не «висит» молча.
  Если собеседник на месте — офер долетает, дальше `call:answer`,
  `call:ice` (в обе стороны, с очередью кандидатов, если ремоут ещё не
  готов) и `call:end`/`call:reject` с любой стороны. Всё это было в целом
  реализовано верно, добавил только обработку недоступного собеседника.
- **getUserMedia в try/catch** — если камеру/микрофон не дали или их нет,
  раньше был необработанный exception; теперь понятный alert и корректный
  откат (звонок не зависает в непонятном состоянии).
- **TURN** — в `app.js` в `rtcConfig` оставлено явное закомментированное
  место, куда вписать свой TURN-сервер, если STUN не пробьёт NAT
  (актуально для мобильного интернета/некоторых операторов).
- Названия полей между фронтом и сервером (`from/to/text/ts`,
  `toUserId/sdp/candidate`, `login/password`, `username/email/password` и
  т.д.) — сверил везде, расхождений нет.

**Осознанно НЕ стал делать (и почему):**
- **SQLite вместо JSON-файлов.** В ТЗ была фраза «проверь SQLite-схему», но
  в проекте изначально используется хранилище на обычных JSON-файлах
  (`server/data/users.json`, `messages.json`) — это сделано специально:
  `better-sqlite3`/`sqlite3` требуют нативной компиляции, которая на
  Termux часто не собирается без танцев с бубном (нужны build-инструменты,
  которые не всегда ставятся гладко). JSON-хранилище работает из коробки
  на чистом `npm install`, ничего не компилирует, и полностью закрывает
  твоё требование «сообщения не пропадают после перезагрузки страницы» —
  история грузится через `GET /api/messages/:withId`. Если всё же
  захочешь именно SQLite позже — скажи, вынесу хранилище в отдельный
  модуль так, чтобы заменить было легко.

## Возможности
- Регистрация/вход (логин + почта + пароль), пароли хранятся только как хэш
- Поиск пользователя по имени, открытие личного чата
- Сообщения в реальном времени (Socket.IO) + история сохраняется и подгружается после перезагрузки страницы
- Индикатор «в сети / офлайн» у собеседника
- Профиль: аватар, имя, username, «о себе»
- Аудио- и видеозвонки (WebRTC): входящий звонок → приём/отклонение → мик/камера on-off → завершение с любой стороны

## Запуск на Termux (Android)

1. Установи Termux (F-Droid, не Google Play — та версия устарела).
2. В Termux:
   ```
   pkg update && pkg upgrade
   pkg install nodejs-lts
   ```
3. Перенеси папку `edward` на телефон (например, через `termux-setup-storage`
   и копирование в `~/storage/downloads/edward`, либо просто `git clone`,
   если выложишь код себе в приватный репозиторий).
4. Установи зависимости и запусти сервер:
   ```
   cd edward/server
   npm install
   npm start
   ```
   Увидишь: `Edward запущен: http://0.0.0.0:3000`

5. Открой на самом телефоне `http://localhost:3000` — проверить, что всё работает.

## Доступ для подруги (туннель)

Ты говорил, что туннель сделаешь сам — подойдёт любой (Cloudflare Tunnel,
ngrok, Tailscale Funnel и т.п.), главное — прокинуть порт `3000` наружу
и отдать подруге получившийся адрес (например `https://xxxx.trycloudflare.com`).

Важно для звонков: браузеры разрешают камеру/микрофон только на `https://`
или `localhost`. Поэтому туннель обязательно должен отдавать **https**
(Cloudflare Tunnel и ngrok это делают из коробки).

## Как пользоваться

1. Оба открывают ссылку на сервер → каждый регистрирует свой аккаунт
   (логин, почта, пароль).
2. Вкладка «Люди» → ищешь подругу по её username → тапаешь → открывается чат.
3. Пишете сообщения — они долетают мгновенно через Socket.IO и сохраняются
   на сервере, так что после перезагрузки страницы вся история на месте.
4. В чате — иконки 📞 (аудио) и 🎥 (видео) для звонка. У собеседника
   выскакивает окно входящего звонка с кнопками принять/отклонить.

## Важные ограничения / что стоит знать

- Это учебная/личная реализация, а не production-мессенджер: шифрования
  сообщений «из конца в конец» нет — сообщения передаются на твой сервер
  и хранятся там в открытом виде (в файле `server/data/messages.json`).
  Раз им пользуетесь только вы двое и сервер твой — это ок, но не выкладывай
  ссылку на туннель никому третьему.
- Данные хранятся в обычных JSON-файлах в `server/data/` — просто для
  надёжности можно иногда копировать эту папку куда-то ещё (бэкап).
- Звонки используют публичный STUN-сервер Google для установления
  соединения (просто чтобы вы нашли друг друга через NAT) — сам голос/видео
  идёт напрямую между вами (peer-to-peer), на сервер не попадает.
  Если звонок не соединяется (бывает при жёстком NAT/мобильном интернете),
  вариант — использовать VPN/Tailscale между телефонами, тогда соединение
  пойдёт стабильнее.
- Держи Termux активным (можно включить wake-lock: `termux-wake-lock`),
  иначе Android «убьёт» процесс и сервер отвалится.

## Как сделать APK, чтобы подруга просто скачала и поставила

Само приложение уже подготовлено как PWA (манифест + иконка + service worker).
Проще всего превратить его в нормальный APK — через бесплатный сервис
**PWABuilder** (делает Microsoft, ничего устанавливать не нужно):

1. Запусти сервер (`npm start`) и подними туннель с **https** — как описано выше.
2. На компьютере открой `https://www.pwabuilder.com`.
3. Вставь свою https-ссылку (адрес туннеля) в поле и нажми «Start».
4. PWABuilder проверит манифест/иконку/service worker (они уже есть в проекте)
   и предложит скачать **Android package** — это и есть готовый `.apk`
   (там будет несколько вариантов, нужен обычный `.apk`, не `.aab`).
5. Пришлёшь этот `.apk`-файл подруге (через тот же чат, облако, флешку —
   как угодно), она включает у себя в Android «Установка из неизвестных
   источников» для этого файла и ставит.
6. Приложение будет открываться иконкой с экрана, без адресной строки —
   но внутри всё равно будет ходить на твой сервер по тому же туннельному
   адресу, так что сервер (Termux) должен быть запущен, когда вы общаетесь.

Важный нюанс: если ты используешь бесплатный временный туннель (например,
`trycloudflare.com`) — при каждом перезапуске адрес меняется, и APK
перестанет находить сервер, пока ты не пересоберёшь его под новый адрес.
Чтобы адрес был постоянным, лучше сделать один из вариантов:
- **Cloudflare Tunnel с именованным туннелем** (нужен свой домен, зато адрес
  не меняется никогда) — тогда APK один раз собрал и всё.
- Либо не пересобирать APK каждый раз, а просто открывать свежую ссылку
  в обычном браузере (без установки) — тогда адрес всегда актуальный.

Альтернатива без APK вообще: у подруги в Chrome на Android открыть твою
ссылку → меню (три точки) → «Добавить на главный экран». Получится точно
такая же иконка и полноэкранный режим без адресной строки, но без сборки
APK — это самый простой и надёжный вариант, если не хочется возиться с
пересборкой при смене адреса.

## Структура проекта

```
edward/
  server/
    server.js       — Express + Socket.IO сервер
    db.js            — простое хранилище на JSON-файлах
    package.json
    data/            — тут появятся users.json и messages.json
  public/
    index.html
    style.css
    app.js
    manifest.json    — манифест PWA (для установки как приложение / сборки APK)
    service-worker.js
    icons/           — иконки приложения (192, 512, 512-maskable)
```
